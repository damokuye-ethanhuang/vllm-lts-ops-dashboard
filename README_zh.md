## 能力清单

| 能力 | 解决什么问题 |
|---|---|
| LTS 查询语义 | 如何正确查询预聚合指标行（Engine 心跳、集群吞吐、KV cache / 提示词 / 生成吞吐），避免结果被放大 10–200 倍。 |
| 每引擎聚合 | 集群总量的正确聚合形态，包括"各引擎 max 之和"模式及其 ~1% 精度验证。 |
| 看板构建与编辑 | 基于 Grafana 数据库的脚本化编辑流程：重新读取、版本号递增、改写断言。 |
| PNG 截图 | 默认折叠行看板的截图方案——渲染 API 与手动截图两条路都有覆盖。 |
| 事故分析 | 基于指标行特征的抢占与慢 TPOT 排查，并明确日志流"证明不了什么"的边界。 |

## 已知坑点

查询 LTS 之前建议先知道这几条；完整清单在 `SKILL.md`：

- 指标行是累计心跳不是采样点——对 gauge/rate 列做 `sum()` 会放大 10–200 倍；有界单引擎指标用 `max()`。
- 单条 SELECT 里嵌套聚合会报 `LTS.2801`；要用分组子查询展平后再聚合。
- LTS 入口按 AK 限流在两位数 req/s 量级——探测循环要加间隔，否则面板会空。
